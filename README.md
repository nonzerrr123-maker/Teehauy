# Teehauy

Teehauy คือเว็บแอป mobile-first สำหรับตีเลขจากความฝัน เก็บเลขและสลากตามงวด ติดตามผลรางวัล และแลกเปลี่ยนชุดเลขในชุมชน

## Stack

- Next.js 16 App Router, React 19 และ TypeScript
- Tailwind CSS 4 และ shadcn/ui
- Supabase Database, Auth และ Storage
- Recharts สำหรับกราฟสถิติ
- Vercel สำหรับ production และ preview deployments

## ฟีเจอร์ปัจจุบัน

- Google Login และ Guest Login ผ่าน Supabase Anonymous Auth
- เชื่อมบัญชี Guest เดิมกับ Google โดยเก็บข้อมูลเดิมไว้
- ตีความหลายสัญลักษณ์จากข้อความฝัน จัดอันดับเลข 2 และ 3 ตัว บันทึกผล และเลือกเผยแพร่สู่ชุมชน
- ตรวจสลาก 6 หลักแบบทันทีครบทุกรางวัล บันทึกสลากจริง และกำหนดการมองเห็นรายใบ
- ผลสลากย้อนหลัง กราฟช่วง 1/5/10 ปีหรือทั้งหมด และการวิเคราะห์งวดถัดไปในหน้าเดียว
- โพสต์ข้อความ ชุดเลขหรือรูปภาพ คอมเมนต์ Like บันทึกโพสต์ และ Follow/Unfollow
- โปรไฟล์สมาชิกสาธารณะพร้อม privacy สำหรับความฝัน ชุดเลข และสลาก
- ธีมสว่าง มืด และตามการตั้งค่าระบบ

## เริ่มต้นในเครื่อง

ต้องใช้ Node.js รุ่นที่รองรับ Next.js 16 และ Supabase project ที่ตั้งค่า Anonymous Auth กับ Google OAuth แล้ว

```bash
npm install
cp .env.example .env.local
npm run dev
```

กำหนดค่าต่อไปนี้ใน `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=

# ไม่บังคับ: ใช้เพิ่ม quota ฝั่ง server สำหรับ RANLOTTO
RANLOTTO_API_KEY=
```

เปิด <http://localhost:3000> ห้าม commit secret หรือ service-role key ลง repository

## Supabase

Schema, functions, indexes และ RLS อยู่ใน `supabase/migrations/` ให้นำ migration ใหม่ขึ้นตามลำดับเวลาและตรวจ Security/Performance Advisors ทุกครั้งที่แก้ฐานข้อมูล

หลักสำคัญของข้อมูล:

- Guest เป็น Supabase user จริง ข้อมูลจึงผูกกับ user ID เช่นเดียวกับบัญชี Google
- Anonymous session อยู่กับ browser storage เดิม การ sign out หรือล้างข้อมูลเว็บไซต์ก่อนเชื่อม Google อาจทำให้กู้บัญชี Guest เดิมไม่ได้
- ความฝันและ prediction เป็น private โดยค่าเริ่มต้น
- สลากเป็น private โดยค่าเริ่มต้น และเจ้าของเลือก `followers` หรือ `public` แยกต่อใบ
- RANLOTTO เป็นแหล่งนำเข้าหลัก ข้อมูลงวดเก็บสถานะการตรวจสอบของผู้ให้บริการแยกจากสถานะในแอป และไม่ยกระดับข้อมูลงวดเก่าเป็นข้อมูลยืนยันโดยอัตโนมัติ
- ตัวตรวจสลากเรียก RANLOTTO จากฝั่ง server และสำรองด้วยผลงวดเต็มที่ยืนยันแล้วใน Supabase จึงไม่เปิดเผย API key ต่อ browser

รายละเอียด migration และการนำเข้าผลสลากอยู่ที่ [`supabase/README.md`](supabase/README.md)

## วิธีตีเลขและวิเคราะห์

- การตีเลขจากข้อความฝันใช้ `thai-symbol-composer-v2` ซึ่งเป็น rule-based engine ไม่ใช่ AI และไม่ใช่ Markov chain
- คลัง `thai-editorial-catalog-v1` มี 333 สัญลักษณ์หลัก 2,154 alias/surface forms ที่ไม่ซ้ำ และ 17 หมวด ครอบคลุมหมวดผลิตภัณฑ์หลัก ได้แก่ บุคคล สัตว์ สิ่งของ ธรรมชาติ สถานที่ เหตุการณ์ ร่างกาย ความตายและลี้ลับ ศาสนาและความเชื่อ ยานพาหนะ และอารมณ์
- ระบบจับทุกสัญลักษณ์ที่ไม่ซ้อนทับกัน เลือกวลีจำเพาะและชื่อ canonical ก่อนคำสั้น รวมคำเรียกแทนเป็นสัญลักษณ์เดียว และใช้สี จำนวน ขนาด การกระทำ สถานที่ และอารมณ์ใกล้เคียงเป็นบริบทในการจัดน้ำหนัก
- คำที่อาจกำกวมจะใช้บริบทรอบข้างก่อน เช่น `โดนเสือกัด` ตีเป็นสัตว์ และ `พี่เสือ` ตีเป็นบุคคล ระบบจะขอให้ผู้ใช้เลือกเฉพาะข้อความที่ยังแยกไม่ได้จริง เช่น `ฝันเห็นเสือ` โดยยังไม่สร้างเลขหรือบันทึกข้อมูลก่อนเลือก
- ผลลัพธ์แสดงเลขฝัน 2 ตัว 6 อันดับและ 3 ตัว 6 อันดับ พร้อมบอกว่าสร้างจากสัญลักษณ์ใด ข้อความเดิมให้ผลเดิม
- หากไม่พบสัญลักษณ์ ระบบจะขอรายละเอียดเพิ่มและไม่สร้างเลขจาก hash หรือเดาความหมายจากข้อความทั้งหมด
- เลขฐานของ core catalog กำหนดรายสัญลักษณ์ ส่วน catalog เสริมใช้ mapping คงที่จาก concept ID แล้วจึงนำบริบทและลำดับความสำคัญมาจัดอันดับ วิธีนี้ไม่ใช้ข้อความฝันทั้งประโยคสร้างเลขสุ่ม และไม่ใช่ค่าความน่าจะเป็น
- การวิเคราะห์งวดถัดไปไม่ใช่ Markov chain เช่นกัน ระบบจัดอันดับจากความถี่เลขตรง 50% ความถี่ตัวเลขแยกตามหลัก 30% และความใกล้ของงวดที่เลขนั้นออกล่าสุด 20%
- หน้าวิเคราะห์แสดงเลข 2 ตัว 6 อันดับจากรางวัลที่ 1 สองหลักท้ายและเลขท้าย 2 ตัว พร้อมเลข 3 ตัว 6 อันดับจากสามหลักท้ายของรางวัลที่ 1 งวดละหนึ่งค่า
- ห้องทดลองแบบจำลองแยก 2 ตัวบน 2 ตัวล่าง และ 3 ตัวบนเป็นคนละลำดับเวลา ตรวจ Markov รายหลักด้วย permutation test ที่ปรับ multiple testing และเปรียบเทียบโมเดลด้วย walk-forward โดยไม่ใช้ผลงวดอนาคตฝึก
- โมเดลถ่วงน้ำหนักเลือก half-life จากข้อมูล validation ก่อนหน้าเท่านั้น และใช้ paired cluster bootstrap/sign-flip test เทียบโมเดล production; ระบบไม่สลับโมเดลจนกว่าช่วงความเชื่อมั่นและผลรายชุดรางวัลจะผ่านเกณฑ์
- คะแนนเป็นเพียงอันดับเชิงสถิติจากผลย้อนหลัง ไม่ใช่ค่าความน่าจะเป็นและไม่รับประกันผลรางวัล

## ข้อมูลผลสลากและการตรวจรางวัล

- ใช้ Public API v1 ของ [RANLOTTO](https://www.ranlotto.com/developers) เป็นแหล่งนำเข้าหลัก พร้อม attribution ตาม license ของผู้ให้บริการ
- นำเข้าคลังย้อนหลังแบบ analysis subset จาก endpoint รายปี และนำเข้าผลงวดเต็ม 173 รายการจาก endpoint ล่าสุด/รายวันที่เลือก
- ผลเต็มครอบคลุมรางวัลที่ 1, ข้างเคียงรางวัลที่ 1, รางวัลที่ 2–5, เลขหน้า 3 ตัว, เลขท้าย 3 ตัว และเลขท้าย 2 ตัว
- เลขทุกชุดเก็บเป็น string เพื่อรักษาเลขศูนย์นำหน้า พร้อม checksum, record ID และ provider verification status ต่อหนึ่งงวด
- ระบบจะประเมินสลากที่บันทึกไว้อัตโนมัติเฉพาะเมื่อนำเข้าผลงวดเต็มที่มีสถานะ `issuer_verified`; คลังผลที่เผยแพร่แต่ยังไม่ยืนยันใช้เพื่อสถิติย้อนหลังเท่านั้น
- RANLOTTO ยังไม่มี API หรือสัญญารูปแบบ QR/barcode ใน OpenAPI ปัจจุบัน จึงยังไม่เปิดการสแกน QR เพื่อหลีกเลี่ยงการอ่านเลขผิด

### ที่มาและการตรวจทานคลังความฝัน

- ความหมายเป็นข้อความเรียบเรียงของ Teehauy โดยใช้กรอบความเชื่อเรื่องการทำนายฝันไทยเป็นบริบท และระบุแหล่งอ้างอิงถึงระเบียน `ตำราทำนายฝัน` ของกรมศิลปากร/หอสมุดแห่งชาติ ไม่ได้คัดลอกข้อความจากเว็บทำนายฝันเชิงพาณิชย์
- ทุกสัญลักษณ์มี `source`, `sourceUrl` และ `reviewStatus` ผลลัพธ์ใน UI แสดงที่มาและสถานะของสัญลักษณ์ที่ถูกใช้จริง
- สถานะ `ตรวจรูปแบบแล้ว` หมายถึงผ่าน schema, จำนวน alias, เลขสามหลัก, id ซ้ำ และ automated tests แล้ว ไม่ได้หมายความว่าผ่านการรับรองโดยนักวิชาการหรือผู้เชี่ยวชาญด้านคติชน
- ตัวเลขและคำตีความมีไว้เพื่อความบันเทิง ไม่ใช่คำแนะนำทางการเงินหรือการรับประกันผลรางวัล
